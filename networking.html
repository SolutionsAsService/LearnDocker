Networks and volumes

Two questions come up in every real project: how does one container reach another, and where does data live when containers come and go?

Finding another container

The name did not resolve. Now create a network of your own and put a container on it:

On a network you create, Docker answers name lookups with the address of the container that has that name. That is what let probe find web in the Compose chapter: Compose creates such a network for each project.

Separately, -p 3000:3000 (as in the images chapter) publishes a container's port on your own machine so you can reach it from outside Docker. Containers on the same network do not need it to reach each other.

Keeping data

Files a container writes go into its own writable layer, and they are deleted when the container is removed. A volume is storage managed by Docker that you attach to a container at a path.

The file written by the first container was there for the second, because both mounted the volume notes. A container that did not mount it saw nothing. Databases, uploads and anything else you cannot afford to lose belong in a volume, or in a folder you mount from your machine (a bind mount, written -v ./folder:/data; we did not run that form here).

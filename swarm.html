Chapter 5

Swarm

Swarm mode lets Docker run a service as several identical tasks and keep that number running. You describe the service and Docker does the rest.

Words used here: a service is the thing you ask Swarm to keep running; a replica (or task) is one running container of it; a rolling update swaps replicas to a new image a few at a time instead of all at once.

What was testedEverything on this page ran on a swarm of one machine, which is enough to see the commands and their effect. Joining other machines uses the worker token that docker swarm init prints; we did not test a multi-machine swarm. Swarm is Docker's own orchestrator; many teams use Kubernetes instead, which this site does not cover.

The last box lists the running tasks. All five now use the new image, and their start times differ by several seconds: Swarm replaced them in turns instead of all at once. We did not send requests during the update, so this page does not show whether the service stayed reachable. You can change how many it replaces together and how long it waits between them with options on docker service update (--update-parallelism and --update-delay; we did not run those options).

When you are done, docker service rm web removes the service and docker swarm leave --force takes this machine out of the swarm.

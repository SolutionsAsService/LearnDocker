Chapter 6

Swarm and Kubernetes

Both documents describe a cluster that runs containers: a swarm of one or more Docker Engines, and a Kubernetes cluster of a control plane and one or more worker nodes. This page sets what each one's documentation says, row by row.

Read this first

Kubernetes was not run for this page. A swarm of several machines was not run either. Every statement about them below is a quotation from the official documentation, with its page and the day it was fetched (2026-11-18).

This site does not teach Kubernetes. Its lessons are Docker commands that were run and printed.

This page does not say which is faster, how many people use either, which is easier to learn, or which one you should choose. No source for any of that was gathered, so the page makes no such statement.

Using a Raft implementation, the managers maintain a consistent internal state of the entire swarm and all the services running on it. S3

What runs on a worker node

Worker nodes are also instances of Docker Engine whose sole purpose is to execute containers. S4

Worker nodes don't participate in the Raft distributed state, make scheduling decisions, or serve the swarm mode HTTP API. S5

kubelet Ensures that Pods are running, including their containers. K6

What you declare

A service is the definition of the tasks to execute on the manager or worker nodes. S9

A Deployment manages a set of Pods to run an application workload, usually one that doesn't maintain state. K9

You describe a desired state in a Deployment, and the Deployment Controller changes the actual state to the desired state at a controlled rate. K10

The unit of work

A task is the atomic unit of scheduling within a swarm. S10

In the Swarm mode model, each task invokes exactly one container. S11

Pods are the smallest deployable units of computing that you can create and manage in Kubernetes. K7

A Pod (as in a pod of whales or pea pod) is a group of one or more containers, with shared storage and network resources, and a specification for how to run the containers. K8

How you reach it

All nodes in the swarm route ingress connections to a running task instance. S12

In Kubernetes, a Service is a method for exposing a network application that is running as one or more Pods in your cluster. K11

Cluster and its nodes

Swarm mode lets you create a cluster of one or more Docker Engines called a swarm. S1

You can create a swarm of one manager node, but you cannot have a worker node without at least one manager node. S6

An odd number N of manager nodes in the cluster tolerates the loss of at most (N-1)/2 managers. S7

Chapter 2

Images

A Dockerfile is a recipe for an image. Build one for a small web server, run it, and then see why the order of its lines decides how fast the next build is.

The app, and the Dockerfile

Make a folder with these four files (the last, .dockerignore, starts with a dot and lists what COPY . . should leave out). The server has no dependencies, so building it needs nothing from the internet except the base image. The files are the ones in this site's lab/hello-node folder, shown here as they are.

Each instruction does one thing:

  • FROM picks the base image everything else is built on.
  • WORKDIR sets the folder later instructions run in, and creates it.
  • COPY copies files from your folder into the image. RUN runs a command while building and keeps the result.
  • EXPOSE and CMD only record settings: which port the app uses, and what to run when a container starts. They add no files.

The .dockerignore file lists what COPY must leave out of the image.

Build it, run it

The last box is the image's layers, newest first. COPY . . added –, npm install –, and the base image underneath is most of the – image.

If the container exits at onceRun docker ps -a to see its status and docker logs NAME for the reason. One cause is that the file named in CMD was never copied into the image.

Why the order of the lines matters

Docker keeps the result of every build step. On the next build it reuses a step if the instruction and the files it copies are unchanged, and if every step before it was reused. After the first step that changes, every later step runs again. We changed one thing at a time and recorded what the build did:

You changedSteps that ran againTime

That is why the Dockerfile copies package.json and installs before it copies the rest of your code. Your source changes often and your dependencies rarely. With this order, editing server.js reuses the install. If the Dockerfile did a single COPY . . before npm install, the rule above says every edit would run the install again (we did not build that variant).

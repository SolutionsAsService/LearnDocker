Chapter 1

Concepts

An image is a read-only template. A container is what Docker starts from an image: a process with its own writable layer on top. Run a few and the difference becomes visible.

Run, list, stop, remove

You need Docker installed and its daemon running; if it is not, follow Docker's install guide. If docker --version prints "command not found", Docker is not installed; if later commands say they cannot connect to the daemon, start Docker (on Docker Desktop, open the app). Each box shows a command, and under it what that command printed when we ran it.

Which shellThe commands were run in a Linux bash shell. Some use curl, head, sleep and $?, which PowerShell and cmd.exe may not have in the same form, and single quotes around --format templates may not work in cmd.exe. On Windows use WSL or Git Bash. We did not run any of this on Windows or macOS.

What just happened

  • The CLI talked to the daemon. The docker command is a client. It sent each request to the Docker daemon (dockerd), which does the work. The hello-world output lists these steps itself.
  • The daemon pulled an image from a registry. hello-world and nginx:alpine were not on this machine, so Docker fetched them from Docker Hub, the default registry. nginx is the image name and alpine is its tag, a label for one version of it.
  • An image became a container. The image is read-only and can start any number of containers. Each container adds its own thin writable layer on top, which is why removing a container does not change the image. The home page shows that layer.
  • A container has a life cycle. It was created and running (Up), then stopped (Exited (0), where 0 means it ended normally), then removed. A stopped container still exists until you remove it, which is why docker ps hides it and docker ps -a shows it.

The words, in one place

WordWhat it is
imageA read-only stack of layers plus settings (what to run, which port to expect). You build it or pull it.
containerA running or stopped instance of an image, with a writable layer on top.
layerOne set of file changes. A Dockerfile instruction that changes files makes one.
tagA label for a version of an image, such as alpine in nginx:alpine.
registryA server that stores images. Docker Hub is the default.
daemonThe background service, dockerd, that builds, runs and manages containers.
CLIThe docker command. It sends requests to the daemon.

Later chapters add Compose, which runs several containers from one file, and Swarm, which runs a service as several copies across machines.
